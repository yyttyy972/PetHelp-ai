# 邻宠帮 HTML 前端

执行方案 Prompt 01–10：接入设计 HTML、认证、档案、AI 发布、匹配、申请、预约、执行及异常处理，保留原 Vue 工程。

## 服务执行与异常

我的→服务记录→预约详情：帮手在预约时段内开始服务，选择清单上传说明或照片，完成必做步骤后提交。购买步骤必须提交照片及实际商品费用。宠主核对记录后验收；结算为模拟记录，不会实际付款。

双方可上报异常、补充沟通；宠主可恢复或终止，批准预算/延期/清单等重要变更后，帮手须核对新版本并确认。凭证按登录权限读取。运行 `npm run test:service` 验证三类正常闭环及部分异常流程，详见 docs/prompt07-acceptance.md。

## 启动

在本目录执行（需先安装 Node.js）：

```sh
npm ci
npm run dev
```

打开 http://127.0.0.1:5174 。端口独立于原 Vue 工程的 5173；端口占用时会明确报错。

## 构建及预览

```sh
npm run build
npm run preview
```

打开 http://127.0.0.1:4174 。输出目录为 `dist/`。

## 当前交付边界

`index.html` 从用户提供的 `pet-help-demo.html` 导入，保留原有 CSS、内嵌图片、原生 JavaScript 和演示数据，追加认证模块入口。已接入真实注册、登录及当前用户查询，后端须在本机 8000 端口运行，Vite 将 `/api` 代理到后端。基础资料无需 AI Key；AI 解析需要后端模型配置。Token 保存在当前标签页的 sessionStorage，刷新保留，关闭标签页结束会话；退出登录清除 Token 和原型草稿，并重载页面清空临时交互。

登录后个人中心姓名和身份来自真实账号。我的资料支持昵称、头像和单一常用地址；我的宠物支持增删改查及照片；服务偏好支持三类服务、宠物类型、区域、半径、费用偏好和可用时间。帮手偏好页面需先保存档案再添加时间。后端新增 `GET /api/v0/helpers/me`，更新代码后须重启后端；完整版本需执行两份增量迁移。

发布页已接入真实 AI、草稿和发布；首页宠主的“我的求助”读取后端需求。任务页提供真实大厅及申请管理；首页推荐提供匹配和帮手详情；“我的→服务记录”提供真实预约查询、双方确认及撤回。服务执行及异常已接入预约详情；聊天消息、未读统计和真实服务评价已接入。原型中的寄养不属于实际服务偏好的支持类型。部署生产环境时须由反向代理将 `/api` 转发到后端；开发代理不是生产部署配置。

## 申请与预约

先按 backend/db/migrations/README.md 执行 001_task_applications.sql，再重启后端。本机已完成该迁移，无需重新初始化旧数据库。

帮手在大厅申请，填写可用时间和服务报酬；宠主在任务页下方选择自己的需求、查看申请并选择帮手。双方在“我的→服务记录”查看预约版本清单并确认；双方确认后成为正式预约。申请阶段不会占用需求或时间。

运行 `npm run test:applications` 可验证申请、选择、双确认、撤回、权限、版本和并发；脚本会创建本地测试数据。

## 大厅和推荐

任务大厅只展示后端公开字段，分页20条，筛选作用于已加载数据。宠主在首页“帮手推荐”选择待匹配需求后点击“查找合适帮手”。服务半径是帮手填写的范围，不是真实距离。推荐解释由现有规则模块生成，不额外调用模型；解释服务失败时保留原始理由。可查看真实帮手档案；预约通过任务页的申请管理创建。

运行 `npm run test:match` 验证真实候选、档案、过滤、分页及公开字段保护。测试会创建本地专用账号、时间段和需求。

## AI 与需求发布

在后端 `.env` 配置 `AI_API_KEY`、`AI_BASE_URL`、`AI_MODEL`、`AI_TIMEOUT`，真实 Key 不提交 Git。选择真实宠物后点击 AI 内容识别；补问与草稿均可查看，最终字段须人工核对。

后端草稿要求必填字段齐全；不完整内容使用“本机暂存”，仅存在当前账号的当前标签页，关闭标签页清除。保存后端草稿后，宠物名单和服务类型锁定。发布需要勾选核对，未保存修改会先保存再发布；已发布需求在本页只读。

预算说明：代买预算为商品预算，无偿服务也可有商品预算；服务报酬在预约阶段约定。时间输入明确使用北京时间，发送带时区数据。普通接口超时15秒，AI解析超时45秒。

运行 `npm run test:requests` 可验证真实 AI、补问、三类服务保存及发布、版本冲突、刷新和失败保留输入。会调用真实模型、产生少量 API 消耗，并向本地库新增专用账号及测试需求，不用于生产库。

## 基础档案真实测试

启动本机后端、数据库及 Vite，安装 Microsoft Edge 后运行 `npm run test:profiles`。脚本使用真实接口，新建带 `html-profiles-` 前缀的本地测试账号，测试资料、宠物、照片、帮手档案、时间段、账号隔离及无效上传；不用于生产库。

后续按执行方案依次接入统一 API 与认证、基础档案、AI 发布及匹配、预约执行、辅助功能。预算映射须区分代买商品预算 `ServiceRequest.budget`、服务报酬 `Booking.agreed_fee` 和实际商品费用 `Booking.actual_cost`。

## 人工验收

1. 打开首页，检查图片、字体、配色、卡片布局。
2. 切换宠主和帮手，检查底部导航及任务页。
3. 打开发布页，检查表单、照片选择和原型草稿操作。
4. 打开个人中心、设置、宠物资料、消息及聊天页面。
5. 分别在手机宽度与桌面宽度检查页面；设计本身采用移动端宽度布局，桌面上不自动改成宽屏设计。

暂不将此目录替换为生产入口；原 `frontend/` 继续保留。
