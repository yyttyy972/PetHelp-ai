# Prompt 02：认证与 API 接入

2026-11-24，分支 feature/html-integration。

## 修改

- js/api.js：统一 Fetch、Bearer Token、15 秒超时、错误解析、401 失效事件、写操作幂等键。网络/5xx 失败保留同一操作的键以供重试；账号切换丢弃旧响应。expected_version 由调用者按实际业务请求体传入，不自动猜测版本。
- js/auth.js：登录/注册弹窗、恢复会话、个人中心真实昵称、角色权限、退出清理。
- css/auth.css：新增弹窗沿用暖色和圆角，原页面样式不替换。
- index.html：仅追加模块入口。
- vite.config.js：/api 代理到 127.0.0.1:8000。

调用接口：POST /api/v0/auth/register、POST /api/v0/auth/login、GET /api/v0/users/me。注册成功后登录失败可直接重试登录，不重复注册。

## 真实验证

使用本机原有 PostgreSQL 数据库及最新工作树后端，Headless Edge：

- 错误密码显示明确错误。
- 演示账号小林登录成功，个人中心返回真实姓名“小林”。
- 刷新后通过 users/me 恢复会话。
- 设置页退出登录后显示登录弹窗。
- 新建一个 html-auth- 时间戳前缀的测试账号，注册并自动登录成功（测试数据保留在本地）。
- 仅 owner 角色账号的 helper 按钮禁用，直接进入帮手页也不会获得 helper 身份。
- 注入无效 Token 后 users/me 返回 401，Token 清除并显示登录弹窗。
- 上述浏览器检查无 pageerror。

环境问题已处理：原启动配置端口为 55432，而当前数据库实际监听 5432；本次启动使用保存的本地凭据并调整进程环境变量端口，没有修改数据库结构，也没有将密码写入项目。

## 边界

原型任务/宠物/聊天仍为演示，不是登录用户的真实业务记录。真实基础档案属于 Prompt 03。本次没有验证 AI、业务并发或完整服务流程。退出仅清除客户端会话，后端 JWT 在有效期内不具备服务端撤销机制。

手工验收：启动后端及本目录 npm run dev → 打开 5174 → 登录 → 查看我的 → 刷新 → 设置退出 → 注册其他角色账号。不要在生产环境使用演示密码。
