# Prompt 07：服务执行、验收与异常

日期：2026-11-24；分支 feature/html-integration。

## 修改

- js/service.js：服务开始、执行记录、受控照片上传/查看、提交验收、宠主核验、异常上报、沟通、恢复、终止及变更重确认。
- js/applications.js：预约详情挂载执行模块，确认/撤回后刷新相关模块。
- tests/service-live.mjs、package.json：真实双账号测试。

本轮无后端或数据库结构变更。复用 bookings 的 start/records/submit/verify/exceptions/confirm，exceptions 的 notes/resolve，以及 requests 的详情/events、media 上传与读取。状态、版本、权限、时间与费用由后端决定。

异常批准可调整预算、结束时间、注意事项、路线要求、现有清单内容和完成条件，并豁免非固定步骤；已执行项目遵守后端不可修改约束。帮助者确认前显示当前预算、时间、注意事项、要求与预约版本清单。终止不自动结算。

## 测试

`npm run test:service` 使用专用账号，构造当前可执行时段，真实浏览器操作三类服务：开始、逐项记录、照片凭证、提交、验收完成；未完成清单时提交被拒绝；宠主不显示开始按钮；凭证可被双方受控读取；完成后帮助者仍可查看记录。

异常流程验证：上报→补充沟通→宠主批准新要求→版本递增→帮手重确认→恢复执行；旧证据及 completed 清单状态保留。另一预约上报后终止，状态为 cancelled。代买商品费用40元加服务报酬10元，模拟结算合计50元。没有真实支付。

修复了清单选择字段与 HTMLFormControlsCollection.item 方法同名造成的读取错误。测试切换新预约时显式刷新列表，不依赖相同 URL 导航触发初始化。

构建通过。验收脚本会留下本机专用测试账号、需求、预约及凭证，不用于生产库。

## 验收入口与边界

我的→服务记录→预约详情。帮手在预约时段内开始服务，选择清单逐项记录，购买步骤需照片及实际费用；宠主核对后验收。双方可上报异常，只有宠主批准或终止，重要变更须帮助者确认。

本轮真实测试覆盖三类正常闭环、新要求重确认和异常终止；延期冲突、预算变更、清单编辑/豁免等全部组合及各种断网/大文件边界尚未逐一完成新版页面自动化测试，不能宣称所有异常场景全覆盖。当前异常清单编辑支持修改现有项目，不提供新增/删除项目；聊天与评价尚未接入。
