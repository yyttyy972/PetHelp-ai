## 运行与部署

后端安装 backend/requirements.txt、requirements-ai.txt。配置 DATABASE_URL、JWT_SECRET（或原有持久化机制）、MEDIA_ROOT；AI_API_KEY/AI_BASE_URL/AI_MODEL/AI_TIMEOUT 写入 backend/.env。本机 Key 已配置，不包含在交付包，不要提交仓库。

新库先执行 backend/db/schema.sql；可按需导入 seed.sql。已有库不要重建。两者都需依次执行：

```powershell
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/001_task_applications.sql
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f db/migrations/002_messages.sql
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

上述命令运行目录为 backend。本机数据库监听5432，配置中的端口须对应实际环境。单进程运行，不宣称支持多实例生产负载。

另开终端进入 frontend-html：

```powershell
npm ci
npm run dev
```

构建执行 npm run build。生产静态服务器部署 dist 并将 /api 反向代理至后端，必须使用HTTPS和自己的账号/密钥。Vite开发代理不是生产服务器。

## 演示顺序

1. 分别用两个浏览器会话登录宠主、帮手，避免混淆账号。
2. 宠主建宠物；帮手填偏好及未来可用时间。
3. 宠主选择宠物、输入需求，展示 AI 补问；补齐字段和清单，核对后发布。
4. 展示大厅公开字段、匹配理由和帮手详情；帮手提交申请，宠主选择。
5. 双方查看预约清单并确认；可在消息中心发送文字，展示未读与历史。
6. 预约到时后开始服务，上传记录，提交验收；宠主核验后评价。
7. 另一个预约演示异常：上报→沟通→批准→帮手确认→恢复，或终止。

开始服务严格受预约时间限制，不修改时间校验来演示。历史 seed 日期可能过期，必须新建需求。金额为模拟结算，不产生真实支付。
