# 第十周 AI 解析真实接口测试记录

## 1. 测试范围

- 接口：`POST /api/v0/ai/parse`
- 环境：本地后端独立 AI 集成入口 `run_ai_integration:app`
- 模型：使用已配置的真实 DeepSeek API Key；本记录不是 Mock 测试
- 身份验证：先登录获取 Bearer Token，再查询当前账号名下宠物并传入对应 `pet_ids`
- 时区：`Asia/Hong_Kong`
- 说明：接口返回的是结构化草稿和补问，不代表已创建或发布正式服务需求

## 2. 测试结果

### 2.1 上门代看（home_visit）

**输入**

> 明天下午帮我上门照看年糕，喂猫粮、换水，注意不要开窗。

**输入宠物**

- `pet_ids`: `00000000-0000-4000-8000-000000000021`（年糕）

**实际返回要点**

- `service_type`: `home_visit`
- `pet_ids`: 正确保留年糕 UUID
- `precautions`: 提取“不要开窗”
- `checklist_items`: 生成 `feed_food`、`change_water` 两项
- `window_start`、`window_end`、`expected_duration_minutes`: `null`
- `questions`: 返回补问列表，涉及具体服务时间、预计时长、费用类型、预算和服务地点等缺失信息

**结论：** 接口成功返回；服务分类、宠物关联、照料事项和禁止事项提取符合输入。时间等缺失字段保持为空并通过补问收集。

### 2.2 宠物用品代买（errand_buy）

**输入**

> 帮我代买一袋猫粮，预算100元以内，送到社区东门，今天晚上18:00前送到。

**输入宠物**

- `pet_ids`: `00000000-0000-4000-8000-000000000021`（年糕）

**实际返回要点**

- `service_type`: `errand_buy`
- `pet_ids`: 正确保留年糕 UUID
- `location`: 社区东门
- `budget`: `100`
- `window_start`: `null`
- `window_end`: `2026-11-16T18:00:00+08:00`
- `checklist_items`: 生成 `purchase`、`delivery` 两项
- `purchase`: `product_name=猫粮`、`quantity=1`、`unit=袋`
- `questions`: 返回补问，涉及费用类型、预计代买/送达时长、商品品牌规格及交接方式等信息

**结论：** 接口成功返回；服务分类、商品名称、数量、单位、预算、送达地点和截止时间均有结构化结果。开始时间及其他未提供信息没有被擅自补造。

### 2.3 上门遛狗（dog_walking）

**输入**

> 明天下午帮我遛狗30分钟，出门前系好牵引绳，结束后送回家。

**输入宠物**

- `pet_ids`: `00000000-0000-4000-8000-000000000022`（建国名下的狗）

**实际返回要点**

- `service_type`: `dog_walking`
- `pet_ids`: 正确保留所选狗 UUID
- `expected_duration_minutes`: `30`
- `requirements`: 提取出门前系牵引绳、结束后送回家
- `checklist_items`: 按 `pickup`、`departure`、`return` 顺序生成三阶段清单
- `window_start`、`window_end`: `null`
- `questions`: 返回补问，涉及具体开始/结束时间、费用、地点、联系人和交接方式等信息

**需复核的问题**

模型另外生成了 `precautions="使用不伸缩牵引绳"`，但用户输入没有提出“不使用伸缩牵引绳”这一要求。这属于未经输入支持的额外约束，不能作为已确认的用户要求交给后续业务流程。建议将该案例标记为需复核，并在后续 Prompt/评估中加入“不得自行增加具体装备限制”的约束。

**结论：** 接口成功返回，分类、时长、宠物关联和三阶段清单正确；存在一项额外生成的安全要求，整体标记为“接口通过、语义质量需复核”。
