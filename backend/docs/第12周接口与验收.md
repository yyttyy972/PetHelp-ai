# 第12周 B：异常处理与联调

本轮新增异常业务和事件查询，不改数据库表结构，沿用主分支取消、幂等和模拟结算。所有路径前缀 /api/v0，需要 Bearer Token；写请求支持 UUID Idempotency-Key，confirm 仍强制提供。异常路径幂等结果与业务更新同事务写 TaskEvent。错误统一 {code,message}。

|方法和路径|请求|响应/权限|
|---|---|---|
|POST /bookings/{id}/exceptions|expected_version,reason_code,description,proposed_change?|201 ExceptionRecord 加 request_status/request_version；预约双方|
|GET /bookings/{id}/exceptions|limit/cursor|200 {items,next_cursor}；预约双方，含历史异常|
|POST /exceptions/{id}/notes|note（非空）|200 TaskEvent；双方，只允许 open|
|POST /exceptions/{id}/resolve|expected_version,resolution（非空）,decision=resume/end,approved_change?|200 ExceptionRecord 加 request_status/request_version；仅宠主|
|POST /bookings/{id}/confirm|expected_version|异常批准后仅帮手确认新版本，恢复 resume_status；响应仍为预约详情|
|GET /requests/{id}/events|limit/cursor|200 {items,next_cursor}；宠主看需求事件，帮手只看自己最近参与预约的事件，过滤 idempotency_result|

异常只能从 reserved/in_service/pending_verify 进入；verification_dispute 仅宠主在 pending_verify 报告，service_timeout 仅 in_service 且数据库当前时间达到 scheduled_end。每预约最多一个 open；新键重复上报返回409 invalid_state，同键重放返回原结果。

proposed_change/approved_change 白名单：budget（非负两位金额）、precautions、requirements、window_end、scheduled_end、checklist_items（完整清单）、waive_item_keys（稳定 item_key 数组）；不得修改宠物名单、服务类型、双方或状态。除可清空文本外不接受显式 null。提议只记录；重要变更批准时 version+1、复制清单及快照、宠主确认新版本，帮手确认清空，异常保持 open，帮手确认新版本后恢复并结案。

已完成、已豁免或已有证据的清单项不能修改或删除；旧证据保留，通过 item_key 跨版本追溯，新增记录使用当前版本清单 id。宠主批准豁免会产生同版本 checklist_waived 事件；固定遛狗/代买执行节点仍需对应记录与购买凭证。

延期只能增加 scheduled_end，必须在批准窗口及单条 Availability 内，并在批准和帮手确认时分别检查其他预约冲突；检查排除本预约。超时后恢复 reserved/in_service 须批准未来结束时间，不能无变更恢复。decision=end 同时取消需求及预约，保留费用和执行记录，不自动结算或重新匹配；不得同时携带 approved_change。

错误：403 forbidden；404 not_found；409 version_conflict/invalid_state/confirmation_pending/time_conflict/schedule_extension_required；422 invalid_change/executed_item_immutable/invalid_window/validation_error。分页 limit 默认20、范围1..100，cursor 为 UUID。

## D 的超时扫描对接

B 提供 app.routers.exceptions.report_exception(c,r,b,u,reason,description,proposed=None)。D 须在同一事务按 ServiceRequest→HelperProfile→Booking 锁定并重读后调用，系统传 u=None；service_timeout 只接受超时 in_service。进入 exception 后不得重复上报；提醒通过 exception_reminder 事件供前端读取。扫描调度和外部通知由 D 后续接入，本 PR 不实现周期扫描。

## 运行与测试

完整后端须同时安装 requirements.txt 与 requirements-ai.txt（C 已合并模块依赖）。在 backend 目录设置 PYTHONPATH 为当前目录，运行 tests/week11.py 与 tests/week12.py；连接 DATABASE_URL 指定的本地测试库，需先导入 schema/seed，测试会新增账号、宠物、需求及执行图片。无数据库迁移。评价 API、交通缓冲仍不在本次实现范围。

批准等待期间 ExceptionRecord 的 resolution/resolved_by/resolved_at 按现有数据库约束保持为空，待结案说明临时保存在 approved_change.resolution，帮手确认后写结案字段；已批准后再次批准返回 confirmation_pending，宠主仍可选择终止。
