# 邻宠帮数据字典 v0.2

已按冻结契约同步第 10 周实现口径（12 表、多宠物）；本次补回身份核验、头像与地址、服务半径、费用双轨、禁止事项、原始需求及宠物照片字段，既有状态与事务设计不变。字段以 API 清单为入口，实现见 backend/db/schema.sql。以下为全部 12 张核心表，物理表名保留指定大小写，PostgreSQL SQL 必须双引号引用（特别是 "User"），字段蛇形小写。NN=NOT NULL，PK=主键，FK=外键，UQ=唯一；未标 NN 的字段允许 NULL。

## 全局规则

每张表均含下列公共字段，属于每张表的完整字段设计，TaskEvent 也不例外：

|字段|类型|约束|说明|
|---|---|---|---|
|id|uuid|PK，默认 gen_random_uuid()|实体标识|
|created_at|timestamptz|NN，默认 now()|创建时间|
|updated_at|timestamptz|NN，默认 now()|服务端更新；事件创建后不改|
|deleted_at|timestamptz|可空，默认 NULL|统一软删除标记|

数据库连接时区固定 UTC，timestamptz 存时间瞬间，API 输出 UTC；birth_date 是日历日期。外键默认 RESTRICT，不级联删除；仅无活动依赖的账号、档案、可用时间及未发布草稿允许软删除，已发布需求、预约、执行、异常、评价和事件保留审计，不提供删除入口；查询默认过滤 deleted_at，审计查询须授权，引用检查还须确认父记录未删除。账号唯一性不因软删除释放，历史清单保留而不软删除。不存在真正删除业务或用户注销后级联抹除历史。

枚举：role_type={owner,helper}；pet_species={cat,dog}；service_type={home_visit,dog_walking,errand_buy}；task_status={draft,pending_match,pending_confirm,reserved,in_service,pending_verify,completed,cancelled,exception}；booking_status={pending_confirm,reserved,in_service,pending_verify,completed,cancelled,exception}；item_status={pending,completed,blocked,waived}；record_kind={item_completed,pickup,departure,return,purchase,delivery}；exception_reason={cannot_enter,pet_hiding,service_timeout,over_budget,out_of_stock,verification_dispute,other}；exception_status={open,resolved}；settlement_status={unsettled,simulated_settled}。所有数组枚举非空且不得重复，由服务端规范化，单社区代码由配置提供，不允许客户端任选社区。

新增逻辑枚举：verification_status={unverified,verified}；fee_type={free,paid}；fee_pref={free,paid,both}，纳入全局枚举约定，三个字段均按本次规格使用 varchar(20) + CHECK 限定取值，不替换既有 PostgreSQL 枚举类型。

## Booking

|字段|类型|约束|说明|
|---|---|---|---|
|request_id|uuid|NN,FK ServiceRequest.id|允许历史取消预约与新预约并存|

|helper_id|uuid|NN,FK HelperProfile.id|帮手账号不得为宠主|
|request_version|integer|NN,CHECK >0|预约确认版本|

|scheduled_start|timestamptz|NN|选定开始时间|
|scheduled_end|timestamptz|NN,CHECK >开始|选定结束时间，须落在窗口且满足预计时长|
|reserved_until|timestamptz|NN|短时预留截止，后续状态不再使用|
|owner_confirmed_at|timestamptz|可空|宠主确认时间|
|helper_confirmed_at|timestamptz|可空|帮手确认时间|
|status|booking_status|NN，默认 pending_confirm|预约生命周期|
|agreed_fee|decimal(10,2)|NN,CHECK >=0|约定服务费；代买与商品预算分开|
|actual_cost|decimal(10,2)|可空,CHECK >=0|商品实际合计，来源购买记录|
|settlement_status|settlement_status|NN，默认 unsettled|仅模拟结算|
|settled_at|timestamptz|可空|模拟结算时间|
|cancel_reason|text|可空|取消原因|

每个需求仅一个非 cancelled 预约：部分唯一索引(request_id) WHERE deleted_at IS NULL AND status<>'cancelled'，包含 completed，禁止完成后再次服务；保留取消历史。simulated_settled 当且仅当 settled_at 非空且 status=completed。状态与确认字段一致性通过服务层校验。

## 索引、事务与跨表约束

新增字段约定：User.verification_status 为身份核验事实来源，HelperProfile.verification_status 为同一账号的同步值，档案创建时继承、核验更新时同事务同步；普通客户端不能自证 verified，核验已定：演示数据直接 verified、新注册 unverified、自证 403 verification_read_only，不在本轮提供核验管理接口。头像可公开，宠物照片与地址按 API 权限投影，URL 仅引用本地受控资源，第 10 周实现受控上传；raw_text 与 precautions 可能含地址等隐私，仅宠主与当前预约帮手可见，历史预约仅保留其有权访问的快照。

fee_type=free 兼容 fee_pref=free/both，fee_type=paid 兼容 paid/both；匹配与创建预约均校验该兼容性和 service_radius_m 范围，距离由匹配模块提供可信计算结果，不能把 address_tag 当精确距离。free 要求 agreed_fee=0，paid 要求 agreed_fee>0，代买 actual_cost 与商品预算独立于服务报酬，无偿代买仍可记录商品费用；既有模拟结算字段及状态不变。fee_type、precautions、raw_text 纳入重要内容与版本快照，变更沿用原有重新确认流程。

为全部 FK 建索引（已被唯一索引首列覆盖者复用），另建 ServiceRequest(status,window_start)、Booking(helper_id,status,scheduled_start,scheduled_end)、Availability(helper_id,start_at,end_at)、TaskEvent(request_id,created_at,id)、ExecutionRecord(booking_id,occurred_at)、ExceptionRecord(booking_id,status)。不要用跨表 CHECK 冒充业务校验。

接单事务先 SELECT ServiceRequest FOR UPDATE，再 SELECT HelperProfile FOR UPDATE，统一锁序；校验需求状态与版本、未过期活动预约、同社区、双方角色、宠物归属、档案支持范围、可用时段包含预约区间，并以 start_a<end_b AND start_b<end_a 检查该帮手所有占用预约。pending_confirm（未过期）、reserved、in_service、pending_verify、exception 均占用时段；completed/cancelled 不占用，超时服务未解决则拒绝该帮手新开服务。检查通过后才插入 Booking 并写事件，同事务改需求 pending_confirm；不能只靠唯一约束或匹配结果避免冲突。所有建单、改时间、修改可用时间、释放预约路径同样遵守锁协议，跨多个帮手按 UUID 顺序锁定；事务失败整体回滚。

角色删除、软删除及可用时间删除必须锁档案并检查活动引用；状态操作锁需求及预约，幂等检查在锁内执行。重要修改包括窗口、时长、地点、预算、交接、联系人、requirements 及所有清单内容，version+1、清空双方确认并留快照与事件；执行中变更按状态表的异常批准流程处理。
